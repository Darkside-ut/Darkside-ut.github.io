# 一、BST（二叉搜索树）

## 1. 二叉树的递归定义

1. 空树是一棵二叉树
2. 一个节点，连同最多两棵作为其子树的二叉树构成一棵二叉树
3. 只有通过规则1进行有限次应用规则2得到的结构，才是二叉树

## 2. 二叉搜索树

- 支持动态操作
- 能够用来构建字典与优先队列
- 基本操作所需的时间与树的高度成正比 —— $O(h)$

### ① BST 的表示方法

- 由一个个独立的节点通过指针连接而成的链式数据结构
- `root(T)`：这是一个特殊的指针，指向整棵树 $T$ 的根节点。只要拿到了这个指针，就能顺藤摸瓜访问整棵树
- 节点内字段：
    - `key`（关键字/键值）：节点中存储的实际数据，BST的排序性质就是基于这个值来判断的
    - `left`（左孩子指针）：指向该节点的左子树的根节点
    - `right`（右孩子指针）：指向该节点的右子树的根节点
    - `p`（父指针）：指向该节点的父节点
        - 根节点没有父节点，所以规定 `p[root[T]] = NIL`
        - 父指针是可选的。如果没有父指针，向上遍历（如找前驱、后继）会很麻烦；如果有，虽然方便了操作，但会占用额外的内存空间

### ② BST 的性质

存储在树中的所有键值（keys）必须满足二叉搜索树性质。这个性质决定了树中元素是如何排列的

对于树中的任意一个节点 $x$：

* **规则 1（左子树）**：对于 $x$ 左子树中的**所有**节点 $y$（用数学符号 $\forall$ 表示“对于所有”），其键值必须满足：`key[y] ≤ key[x]`
    * *即：左子树里的所有值，都小于或等于根节点的值*
* **规则 2（右子树）**：对于 $x$ 右子树中的**所有**节点 $y$，其键值必须满足：`key[y] ≥ key[x]`
    * *即：右子树里的所有值，都大于或等于根节点的值*

### ③ BST 的遍历

#### Ⅰ. 中序遍历

正是由于二叉搜索树性质：左<根<右，使得我们可以通过递归的方式进行中序遍历，从而将树中所有的键值（keys）按照从小到大的顺序打印出来

```pseudocode INORDER-TREE-WALK(x)
if x ≠ NIL then
    INORDER-TREE-WALK(left[x])
    print key[x]
    INORDER-TREE-WALK(right[x])
@note 遍历需要多长时间？O(n)
```

```fold 证明中序遍历算法的正确性
要证明：
1. **能打印出所有元素**
2. **打印顺序是升序的**
3. **算法能够终止**

证明方法：对树的大小进行归纳

* **基础情况：空树**
    * 空树没有元素需要打印，算法直接返回，显然成立

* **归纳假设 ：**
    * 假设对于所有节点数小于 $n$ 的树，中序遍历算法都是正确的（能按升序打印所有元素并终止）

* **归纳步骤：Size $\ge$ 1**
    * 此时树不为空，设根节点为 $x$。根据算法代码，它会按顺序执行三个步骤，我们分别证明：
    * **a. 打印左子树**：根据归纳假设，左子树的节点数必然小于整棵树，因此对左子树调用中序遍历是正确的。它会把左子树的所有元素**按升序打印**出来
    * **b. 打印根节点**：接下来打印根节点 $x$。根据**二叉搜索树的性质**，左子树中的所有元素都 $\le key[x]$。因此，刚打印完的左子树序列，加上现在的根节点，**依然是升序的**
    * **c. 打印右子树**：最后对右子树调用中序遍历。同样根据归纳假设，右子树会按升序打印。又因为BST性质保证右子树的所有元素都 $\ge key[x]$，所以接在根节点后面打印的右子树序列，使得整体序列**依然保持升序**
```

#### Ⅱ. 前序遍历

前序遍历的顺序是：根 -> 左 -> 右。即先访问当前节点，然后递归遍历左子树，最后递归遍历右子树

```pseudocode INORDER-TREE-WALK(x)
if x ≠ NIL then
    print key[x]
    INORDER-TREE-WALK(left[x])
    INORDER-TREE-WALK(right[x])
@note 遍历需要多长时间？O(n)
```

#### Ⅱ. 后序遍历

后序遍历的顺序是：左 -> 右 -> 根。即先递归遍历左子树，再递归遍历右子树，最后才访问当前节点

```pseudocode INORDER-TREE-WALK(x)
if x ≠ NIL then
    INORDER-TREE-WALK(left[x])
    INORDER-TREE-WALK(right[x])
    print key[x]
@note 遍历需要多长时间？O(n)
```

### ④ BST 的查询

* **最好/平均情况（平衡树）**：$h = \Theta(\lg n)$，操作时间 $O(\lg n)$。包含随机生成的树，以及**自平衡树**（如红黑树、AVL树、2-3树）
* **最坏情况（不平衡树）**：树退化成线性链表，$h = \Theta(n)$，操作时间退化为 $O(n)$

#### 查询指定值

##### 尾递归搜索

```pseudocode TreeSearch(x,k)
if x =NIL or k = key[x] then
    return x
if k < key[x] then
    return TreeSearch(left[x],k)
else
    return TreeSearch(right[x],k)
@note 运行时间：O(h)
@note 更加直接的查询方法
```

##### 迭代搜索

```pseudocode IterativeTreeSearch(x,k)
while x ̸= NIL and k ̸= key[x] do
    if k < key[x] then
        x ←left[x]
    else
        x ←right[x]
return x
@note 更高效的查询方法
```

#### 查询最大/最小值

二叉搜索树的性质保证了最小值一定出现在最左端结点，最大值出现在最右端结点

```pseudocode TreeMinimum(x)
while x ̸= NIL do
    x ←left[x]
return x
```
```pseudocode TreeMaximum(x)
while x ̸= NIL do
    x ←right[x]
return x
```

### ⑤ 前驱和后继

**定义**：节点 $x$ 的后继，是树中大于 $x$ 键值的节点中，最小的那一个。最大键值的后继为 NIL
* **情况 1（有右子树）**：如果 $x$ 有右子树，后继就是**右子树中的最小值**
* **情况 2（无右子树）**：如果 $x$ 没有右子树，后继就是 $x$ 的**最低祖先** $y$，且必须满足 $x$ **位于 $y$ 的左子树中**

寻找后继的伪代码：
```pseudocode TreeSuccessor(x)
if right[x] ̸= NIL then
    return TreeMinimum(right[x])
y ←p[x]
while y ̸= NIL and x = right[y] do
    x ←y
    y ←p[y]
return y
@note 与寻找前驱的代码完全对称
@note 运行时间：O(h)
```

### ⑥ 元素的插入和删除

#### 元素插入

插入和删除元素的前后要始终保持 BST 的性质

```pseudocode TreeInsert(T, z)
y ← NIL
x ← root[T]
while x ̸= NIL do
    y ← x
    if key[z] < key[x] then
        x ← left[x]
    else
        x ← right[x]
p[z] ← y
if y = NIL then
    root[T] ← z
else if key[z] < key[y] then
    left[y] ← z
else
    right[y] ← z
```

时间复杂度：
* **初始化**：$O(1)$
* **查找插入位置**：$O(h)$
* **执行插入**：$O(1)$
* **总时间复杂度**：$O(h)$

#### 元素删除

* **情况 0（叶子节点）**：$x$ 没有子节点，直接删除
* **情况 1（单分支节点）**：$x$ 只有一个子节点，用其子节点替换它（让父节点指向子节点）
* **情况 2（双分支节点）**：$x$ 有两个子节点。先找到 $x$ 的**后继节点**（右子树的最小值），将其内容与 $x$ 交换，然后把问题转化为删除那个后继节点（此时必然属于情况 0 或 1）

```pseudocode TREEDELETE(T, z)
if left[z] = NIL or right[z] = NIL then
    y ← z
else
    y ← TREESUCCESSOR[z]
if left[y] ≠ NIL then
    x ← left[y]
else
    x ← right[y]
if x ≠ NIL then
    p[x] ← p[y]
if p[y] = NIL then
    root[T] ← x
else if y ← left[p[y]] then
    left[p[y]] ← x
else
    right[p[y]] ← x
if y ≠ z then
    key[z] ← key[y]
return y

@note 1. 首先将 case 2 转为 case 0 或 1，用 y 记录 z 或 z 的后继
@note 2. 其次用 x 记录 y 的孩子，并将 y 的 parent 设置为 x 的 parent，再修改 y 的 parent 的左右孩子改为 x
@note 3. 最后，如果 y 是 z 的后继，则用 y 的值覆盖 z 的值，返回被删除的结点 y
```

```fold 删除操作的正确性
* **核心疑问**：当删除有两个孩子的节点（Case 2）时，为什么找它的后继节点就能保证问题一定会降级为 Case 0 或 Case 1，而不会再遇到一个有两个孩子的情况？
* **解答**：因为 Case 2 找的是**右子树中的最小值**。这个后继节点**绝对不可能有左孩子**（如果有左孩子，那他自身就不是右子树的最小值）。既然没有左孩子，它最多只有右孩子，所以必然完美落入 Case 0 或 Case 1
* **扩展思考**：可以换成前驱节点（左子树的最大值）来替换吗？
    * **可以**。原理完全对称（前驱绝不可能有右孩子）
    * **进阶技巧**：在实际工程中，可以**交替使用前驱和后继**。如果总是用同一边的节点来替换，树可能会越来越偏向另一边（形成“歪脖子树”），交替使用有助于保持树的相对平衡
```

### ⑦ 排序

使用元素的插入来创建 BST，使用中序遍历将元素读出

```pseudocode Sort(A)
for i ← 1 to n do
    TreeInsert(A[i])
InorderTreeWalk(root)
```

时间复杂度分析：

* **最好情况**：插入序列随机，建成的树是平衡的，单次插入 $O(\log n)$。总时间为 $n \times O(\log n) + O(n) = O(n \log n)$
* **最坏情况**：插入序列已有序，树退化成链表，单次插入 $O(n)$。总时间为 $n \times O(n) + O(n) = O(n^2)$

# 二、RB Tree（红黑树）

## 1. 相关定义
* 红黑树是二叉搜索树的一种变体，旨在确保树是平衡的
* 树高为 $O(\lg n)$，其中 $n$ 是节点的数量
* 在最坏情况下，操作耗时为 $O(\lg n)$
* 二叉搜索树每个节点 + 1 个比特：属性 `color`，其值为红（red）或黑（black）
* 继承二叉搜索树的所有其他属性：`key`、`left`、`right` 和 `p`。
* 所有空树（叶子）都被涂成黑色
    1. 为了节省空间和简化边界代码，所有叶子节点的空指针都指向一个全局共享的哨兵节点 `nil`，`color[nil] = black`
    2. 根节点的父指针 `p` 也指向这个 `nil` 哨兵

## 2. RB Tree 的性质

### ① RB Tree 要求

1. **颜色限制**：每个节点必须是红色或黑色
2. **根节点**：根节点必须是黑色
3. **叶子节点**：所有叶子节点（NIL空指针）都是黑色的
    * 这意味着每个“真实”节点都有两个子节点（要么是真实节点，要么是NIL）
4. **红节点限制**：如果某个节点是红色，那么它的两个孩子必须是黑色。
    * 即任何路径上不能出现连续的红色节点
5. **黑高平衡**：对任意节点，从该节点出发到其所有后代叶子（NIL）的路径上，包含的黑色节点数量必须完全相同

### ② 树高与黑高

**1. 节点的高度 (Height)**

* **定义**：从该节点向下走到叶子节点（NIL）的**最长路径**上的**边数**
    * **例**：看图 2 的根节点 26，它的最长路径是 `26 -> 41 -> 30 -> 38 -> nil`，一共经过了 4 条边，所以高度 $h = 4$

**2. 节点的黑高 (Black-height, $bh(x)$)**

* **定义**：从节点 $x$ 出发（不包含 $x$ 自身），向下走到任意叶子节点（NIL）的路径上，经过的**黑色节点数量**（包含最后的 NIL 节点）
* **核心性质**：根据红黑树黑高平衡的性质，从同一个节点出发到所有叶子的路径，其黑色节点数量必须相等。因此，黑高是一个**确定的、唯一的值**
    * **例**：看节点 38（红色），它的路径是 `38 -> nil`。不算 38 本身，最后是黑色的 `nil`，所以黑高 $bh = 1$
    * **例**：看节点 30（黑色），它的路径向右是 `30 -> 38(红) -> nil(黑)`，向左是 `30 -> nil(黑)`。不算 30 本身，两条路径都只包含 1 个黑节点（`nil`），所以黑高 $bh = 1$
    * **例**：看根节点 26，不算 26 自己，向下走到叶子的任意路径，都恰好包含 2 个黑节点（例如 `26 -> 41(红) -> 47(黑) -> nil(黑)`，包含 47 和 nil 两个黑节点），所以它的黑高 $bh = 2$

**3. 红黑树的黑高 (Black-height of a tree)**

* **定义**：整棵红黑树的黑高，就等于**根节点的黑高**
    * **例**：图中的红黑树，其整体黑高就是根节点 26 的黑高，即 2

**4. 黑高与高度的关系：**
* 对于高度为 $h$ 的节点，其黑高**至少为** $\lceil h/2 \rceil$（或写为 $bh \ge h/2$）
    * 因为红黑树性质规定“不能有连续的红节点”，所以在一半的路径上（最坏情况就是红黑交替），必然存在黑节点

**5. 红黑树高度定理：**
* 包含 $n$ 个内部节点的红黑树，其高度 $h \le 2\lg(n + 1)$
    * 这说明红黑树的高度始终被限制在 $O(\log n)$ 级别
```fold 红黑树高度定理证明
先证明引理：
以节点 $x$ 为根的子树中，**至少包含** $2^{bh(x)} - 1$ 个内部节点

**1. 归纳法证明引理**
* **基础情况**：高度为 0 的节点是空叶子
    * 其黑高 $bh = 0$
    * 子树节点数 $\ge 2^0 - 1 = 0$（成立）
* **归纳步骤**：假设高度为正的节点 $x$ 有两个孩子
    * 无论 $x$ 是红是黑，它的两个孩子节点的黑高只能是 $bh(x)$（当 $x$ 是红节点时）或 $bh(x) - 1$（当 $x$ 是黑节点时）
    * 根据归纳假设，左右子树各自至少包含 $2^{bh(x)-1} - 1$ 个内部节点
    * 加上根节点 $x$ 自身，总节点数至少为：$(2^{bh(x)-1} - 1) + (2^{bh(x)-1} - 1) + 1 = 2^{bh(x)} - 1$

**2. 推导最终定理**

* 将整棵红黑树看作以 `root` 为根的巨大子树。其真实节点总数 $n \ge 2^{bh(root)} - 1$
* 根据前一页的结论：黑高 $bh(root) \ge h/2$
* 代入不等式：$n \ge 2^{h/2} - 1$
* 两边加 1 并取对数：$\lg(n + 1) \ge h/2 \implies h \le 2\lg(n + 1)$
* **最终结论**：红黑树的高度 $h = O(\lg n)$
```

## 3. RB Tree 的操作

### ① 旋转

**核心作用**：旋转是改变树结构的基础操作。当树失去平衡时，通过旋转可以在不破坏数据顺序的前提下，调整节点的上下层级

**操作类型（互为逆操作）**：
* **右旋 (rightRotate(y))**：把节点 $y$ 往下压，把它的左孩子 $x$ 往上提变成新的根
* **左旋 (leftRotate(x))**：把节点 $x$ 往下压，把它的右孩子 $y$ 往上提变成新的根

<p align="center">
  <img src="/devices/9.png" alt="红黑树的旋转">
  <br>
  <small>figure 3：红黑树的旋转</small>
</p>

**两大特性**：
1. **保持 BST 性质**：无论怎么转，中序遍历（从小到大）的顺序永远不变（如 $A < x < B < y < C$）
2. **极快的时间复杂度**：$O(1)$
    - 因为旋转本质上是**原地修改几个指针**（只改变父子的连接关系），不涉及节点的移动或数据的复制

### ② 插入

1. **初始动作**：像普通二叉搜索树一样插入新节点 $x$，并且强制将 $x$ 涂成红色
    * 原因：涂成红色不会改变路径上的黑色节点数量，不会违反黑高平衡的性质

2. **检查性质2（根节点必须是黑色）**：
    * 如果 $x$ 刚好插成了整棵树的根节点，且是红色，那就直接把它涂黑即可

3. **检查性质4（不能有连续的红节点）**：
    * 如果不是根节点，但它的父节点 $p[x]$ 也是红色（说明出现了“红-红”冲突），那就将冲突（违规）不断地向上移动，直到找到一个可以修复的位置

**伪代码**：

```pseudocode RBINSERT(T, x)
TREEINSERT(T, x)
color[x] ← RED
while x ≠ root[T] and color[p[x]] = RED do
    if p[x] = left[p[p[x]]] then
        y ← right[p[p[x]]]
        if color[y] = RED then
            color[p[x]] ← BLACK
            color[y] ← BLACK
            color[p[p[x]]] ← RED
            x ← p[p[x]]
        else
            if x = right[p[x]] then
                x ← p[x]
                LEFTROTATE(x)
            color[p[x]] ← BLACK
            color[p[p[x]]] ← RED
            RIGHTROTATE(p[p[x]])
    else
        same as above, but exchanging 'right' and 'left'
color[root[T]] ← BLACK
```

### ③ 删除

#### 阶段一：执行普通 BST 的删除

你要删除的目标节点设为 $Z$

1. **$Z$ 有两个孩子：**
    * **操作**：找到 $Z$ 的后继节点 $Y$（右子树的最小值）。把 $Y$ 的值复制给 $Z$，然后**把删除目标变成 $Y$**
    * **结果**：因为 $Y$ 是最小值，它绝对没有左孩子，所以问题转化为了情况 2 或 3

2. **$Z$ 只有一个孩子：**
    * **操作**：让这个唯一的孩子 $X$ 顶替 $Z$ 的位置
    * **结果**：
        - 如果 $Z$ 是红色的，直接把 $X$ 涂黑
        - 如果 $Z$ 是黑色的，$X$ 将继承“额外的一层黑色”，变成 **“双黑节点”**，进入阶段二

3. **$Z$ 是叶子节点（没有孩子）：**
    * **操作**：直接删除 $Z$（用 NIL 顶替）
    * **结果**：
        - 如果 $Z$ 是红色的
        - 如果 $Z$ 是黑色的，这个 NIL 节点变成 **“双黑节点”**，进入阶段二

#### 阶段二：修复阶段一产生的 “双黑节点”

现在，当前节点 $X$ 是一个 “双黑” 节点。我们需要把这层多出来的黑色消除掉

**修复的核心思路：看兄弟的脸色行事**

（假设 $X$ 是左孩子，如果 $X$ 是右孩子则完全对称）

1. **情况 1：兄弟是红色 (Red Sibling)**

    * **特征**：$X$ 的兄弟是红节点
    * **操作**：父节点变红，兄弟变黑，**对父节点左旋**
    * **结果**：此时 $X$ 有了一个新的兄弟（原本红兄弟的黑孩子），变成了黑色。**转化为情况 2、3 或 4**

    * **操作**：兄弟变红，**双黑上移**（把多出来的黑色交给父节点）

# 三、扩充数据结构

通过 “扩充（augment）” 标准数据结构来实现，也就是在节点中存储额外的信息

新增的额外信息不能是死数据，它必须能够随着数据结构的常规操作（如插入、删除、旋转）被自动且高效地更新和维护

## 1. Order-Statistic Tree 顺序统计树

**核心目的：** 给红黑树打补丁，使其能够支持快速的顺序统计（order-statistic）操作（例如：快速找到第 $i$ 小的元素，或者查询某个元素的排名）

**如何扩充：**

1. **保留原属性**：保留红黑树原有的 `key`、`color`、`p`、`left`、`right` 字段
2. **新增字段**：增加一个 `size[x]` 字段
    - **`size[x]` 的含义**：以节点 $x$ 为根的子树中，包含的内部节点总数（包括 $x$ 自身）
3. **维护公式**：`size[x] = size[left[x]] + size[right[x]] + 1`。
    * 注：哨兵节点的 `size[nil[T]] = 0`，即空子树大小为 0

> 通过在节点里存下 “以我为根的子树有多大” 这样的信息，我们后续就能像查字典一样，利用大小信息快速向左或向右导航，从而在 O(logn) 时间内找到第 i 小的元素

**Example：**

> 上方是键值（key），下方是子树大小（size）

* **允许重复键值**：在顺序统计树中，键值（key）不要求唯一，可以有相同的值（例如图中的有两个 14）
* **排名的定义（Rank）**：当存在相同键值时，一个元素的 “排名” 被明确定义为**这棵树进行中序遍历时该元素被打印的位置**
    * 含义：比如在这棵树上做中序遍历，得到的序列是：`3, 7, 10, 12, 14, 14, 16`。那么第一个 `14` 的排名就是 5，第二个 `14` 的排名就是 6

### ① 查找第 $i$ 小的元素

- 伪代码

``` pseudocode OSSELECT(x, i)
r ← size[left[x]] + 1
if i = r then
    return x
else if i < r then
    return OSSELECT(left[x], i)
else
    return OSSELECT(right[x], i - r)
@note 左子树根的 size + 1 就是当前结点的排名
@note 向右找的时候，因为左子树和根节点已经占了 r 个位置，所以我们在右子树里要找的是第 i - r 小的元素
```
- **时间复杂度**：因为每次只走树的一条分支（从根向下），高度为 $O(\log n)$，所以运行时间为 $O(\log n)$

### ② 查询某个节点 $x$ 的排名

- 伪代码

```pseudocode OSRANK(T, x)
r ← size[left[x]] + 1
y ← x
while y ≠ root[T] do
    if y = right[p[y]] then
        r ← r + size[left[p[y]]] + 1
    y ← p[y]
return r
@note 先确定 x 在当前子树中的排名 r，用 y 记录 x
@note 然后判断 y 是不是右孩子，如果是，则说明父节点和父节点的左子树都比 y 小。因此，要把父节点的左子树大小加上父节点本身累加到 r 上；如果不是，则不需要累加。
@note 最后让 y 向上移一层
```

* **时间复杂度**：过程就是沿着树向上走到根节点，所以耗时与树高成正比，最坏为 $O(\log n)$

### ③ size 的维护

* **插入操作时的维护**：
    1. `TREE-INSERT`（**向下寻找位置**）：在从根节点向下走到叶子节点的路径上，每经过一个节点，就把它的 `size` 加 1。耗时 $O(\log n)$
    2. `ROTATE`（**旋转调整**）：红黑树的旋转虽然改变了树结构，但每次旋转只影响**两个节点的 `size`**。只需重新计算这两个节点的 `size` 即可。耗时 $O(1)$

## 2. Interval Trees 区间树

1. **区间表示法**：把闭区间 $[t_1, t_2]$ 抽象为一个对象 $i$。包含两个字段：`low[i] = t1`（低端点）和 `high[i] = t2`（高端点）

2. **区间三分律**：任意两个区间 $i$ 和 $i'$ 的关系，有且仅有以下三种情况之一：
    * 两者**重叠**
    * $i$ 在 $i'$ 的**左侧**（即 $i$ 的右端点 < $i'$ 的左端点）
    * $i$ 在 $i'$ 的**右侧**

```fold 区间树具体设计方案
1. **选择底层数据结构**：
    * 使用红黑树
    * 每个节点 $x$ 存储一个区间 `int[x]`
    * **排序依据**：节点 $x$ 的键值设为区间的**低端点** `low[int[x]]`

2. **确定附加信息**：
    * 新增字段 `max[x]`
    * **含义**：以节点 $x$ 为根的子树中，所有区间的**最大端点值**

3. **验证信息可维护性**：
    * **维护公式**：`max[x] = max(high[int[x]], max[left[x]], max[right[x]])`
        - 即：当前节点区间的高端点、左子树的最大端点、右子树的最大端点，三者取最大值
    * **时间复杂度**：因为 $max$ 值完全可以由左右孩子的信息推导出来，所以在红黑树进行插入、删除和旋转时，可以在 $O(\log n)$ 的时间内顺带更新完

4. **开发新操作**：
    * 基于上述设计，开发 `INTERVAL-SEARCH(T, i)` 算法，用于查找重叠的区间
```

### ① 查找重叠区间

- 伪代码

```pseudocode INTERVALSEARCH(T, i)
x ← root[T]
while x ≠ nil[T] and i does not overlap int[x] do
    if left[x] ≠ nil[T] and max[left[x]] ≥ low[i] then
        x ← left[x]
    else
        x ← right[x]
return x
@note 只要当前节点不是空，且当前节点代表的区间与目标区间没有重叠，就一直往下找
```

- 时间复杂度：区间搜索和普通的二叉搜索一样，每次都会剪掉一半的子树，所以查找时间被严格限制在对数级别 O(logn) 内
