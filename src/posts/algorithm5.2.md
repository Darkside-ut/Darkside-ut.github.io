# 一、Binomial Heap 二项堆

## 1. 可合并堆

一种支持高效合并操作的数据结构
* **5个基础操作**：
    1. `MAKE-HEAP()`：创建一个空堆
    2. `INSERT(H, x)`：将元素 $x$ 插入堆 $H$
    3. `MINIMUM(H)`：返回堆中的最小元素
    4. `EXTRACT-MIN(H)`：返回并删除最小元素
    5. `UNION(H1, H2)`：合并两个堆（这是可合并堆与传统二叉堆最大的区别）

* **其他操作**：
    * `DECREASE-KEY`：降低指定元素的键值
    * `DELETE`：删除指定元素

* **典型应用**：Dijkstra 最短路径算法、Prim 最小生成树算法、事件驱动模拟、哈夫曼编码、堆排序等

## 2. 二项树的递归定义

* **基础情况**：$B_0$ 是一棵只包含单个节点的树
* **递归构造**：$B_k$ 由两棵 $B_{k-1}$ 连接而成。连接方式：其中一棵 $B_{k-1}$ 的根，成为另一棵 $B_{k-1}$ 根的**最左孩子**

## 3. 二项树的性质

* **节点总数 = $2^k$**
    * *理解*：每次拼接两棵 $B_{k-1}$，节点数翻倍

* **树的高度 = $k$**
    * *理解*：从根到最深叶子节点的边数

* **根节点的度数（孩子数） = $k$**
    * *理解*：结合右侧配图，$B_k$ 的根节点长出了 $k$ 个孩子，分别是 $B_{k-1}, B_{k-2}, \dots, B_0$ 的根

* **删除根节点后，会分裂出 $k$ 棵二项树**
    * *理解*：也就是刚才提到的 $B_{k-1}, B_{k-2}, \dots, B_0$。这个性质在 `EXTRACT-MIN` 操作中非常关键

* **第 $i$ 层（深度为 $i$）的节点数为组合数 $\binom{k}{i}$**
    * *理解*：这也正是 “二项树 (Binomial Tree)” 这个名字的由来（深度从 0 开始，节点分布规律完美契合二项式展开的系数，如杨辉三角）

## 4. 二项堆的定义

**定义**：二项堆是由一组二项树组成的序列，必须同时满足以下两个性质：

1. **最小堆有序（Min-heap ordered）**：每棵二项树内部都满足最小堆的性质（即父节点的值 $\le$ 子节点的值）
2. **度数唯一性**：对于任意阶数 $k$，堆中**最多只包含 0 或 1 棵 $B_k$**（即不存在两棵度数相同的二项树）

## 5. 二项堆的实现

* **节点的内部表示（3个指针）**：
    * 采用 **“左孩子、右兄弟”** 的表示法
    * 每个节点包含三个字段：`parent`（父节点）、`left`（最左边的孩子）、`right`（紧挨着的右侧兄弟）
    * 好处：这种表示法可以把任意多叉树转化为二叉树结构，极大地节省了指针空间，不需要为每个可能的孩子分配指针数组

* **根链表的组织**：
    * 所有二项树的根节点通过一个**单向链表**连接起来
    * **关键特性**：沿着根链表遍历时，各棵树的**度数是严格递增的**（从右向左或从左向右递增，取决于实现约定，通常从小度数依次向后连接）

## 6. 二项堆的性质

1. **最小值的位置**：最小键值一定在根链表的某个根节点上（$B_0, B_1, \dots, B_k$ 的根中找）
2. **与二进制表示的完美对应**：堆中包含 $B_i$ 当且仅当 $N$ 的二进制表示中第 $i$ 位为 1
3. **树的数量上限**：最多包含 $\lfloor \log_2 N \rfloor + 1$ 棵树（即 $N$ 的二进制位数）
4. **高度上限**：整棵树（实际上是单棵子树）的最大高度不超过 $\lfloor \log_2 N \rfloor$

## 7. 二项堆的合并

* **基本概念**：二项堆是一种 “可合并堆”。将两个二项堆 $H'$ 和 $H''$ 合并成一个新堆 $H$，基本操作（如连接根节点）只需 $O(1)$ 的时间
* **合并同类项（最容易的情况）**：
    * 如果 $H'$ 和 $H''$ 恰好都只包含一棵度数相同的二项树（比如都是 $B_k$），合并非常简单：
        1. 直接连接这两个树的根节点
        2. 比较两个根节点的键值，**让较小的键值作为新树（新堆）的根**

- **时间复杂度：**

    **最终时间复杂度**：$O(\log N)$

    **为什么是 $O(\log N)$？**

    * 耗时与两个根链表中的**树的棵数**成正比
    * 包含 $N'$ 个节点的堆 $H'$，最多有 $\lfloor \log N' \rfloor + 1$ 棵树
    * 包含 $N''$ 个节点的堆 $H''$，最多有 $\lfloor \log N'' \rfloor + 1$ 棵树
    * 合并时最多只需遍历这两条根链表：$\lfloor \log N' \rfloor + 1 + \lfloor \log N'' \rfloor + 1$。由于 $N' + N'' = N$，所以总遍历次数上限不超过 $2(\lfloor \log N \rfloor + 1)$
    * 因此，运行时间与 $\log N$ 成正比

## 8. 删除最小元素

* **三大步骤**：
    1. **找并删**：遍历根链表，找到键值最小的根节点 $x$，将其从根链表断开并删除
    2. **拆分子树**：把 $x$ 的所有孩子（它们分别是一棵棵独立的二项树）拆下来，组成一个新的二项堆 $H'$
    3. **重新合并**：把拆分出来的新堆 $H'$ 与原来的堆 $H$（剩下的部分）执行 `UNION`（**合并**）操作，得到最终的新堆

* **时间复杂度**：$O(\log N)$
    * 找最小值：$O(\log N)$（遍历根链表）
    * 拆分孩子：$O(\log N)$（度数最大为 $\log N$）
    * 合并 (Union)：$O(\log N)$
    * 三者相加，总时间依然是 $O(\log N)$

## 9. 减小键值 key

* **目标**：将节点 $x$ 的键值减小
* **操作步骤**：
    1. 找到节点 $x$（假设它在某棵 $B_k$ 树中）
    2. 如果降低后的键值变得**比它的父节点还要小**（违反了最小堆性质），就执行 “冒泡” 操作：不断将节点 $x$ 与它的父节点交换位置，直到满足堆性质为止

* **时间复杂度**：$O(\log N)$
    * 最坏情况下，节点 $x$ 需要一路冒泡到根节点。冒泡的次数也就是节点 $x$ 的深度
    * 因为二项树的最高深度不超过 $\lfloor \log_2 N \rfloor$，所以最大交换次数也就是 $O(\log N)$

## 10. 删除节点

* 删除二项堆 $H$ 中的节点 $x$：
    1. 将 $x$ 的键值减小至 $-\infty$
    2. 执行 `DELETEMIN`（删除最小元素）

* 运行时间：$O(\log N)$

## 11. 插入节点

**二项堆：插入**

* 将新节点 $x$ 插入二项堆 $H$ 中
    1. $H' \leftarrow \text{MAKEHEAP}(x)$
    2. $H \leftarrow \text{UNION}(H', H)$

* 运行时间：$O(\log N)$

# 二、Fibonacci Heaps 斐波那契堆

## 1. 斐波那契堆的结构

* **基本结构**：一组最小堆有序树的集合。树与树之间没有任何度数限制，可以任意形态

* **节点指针**：
    * 每个节点包含指向父节点（parent）和任意一个孩子（child）的指针
    * 孩子节点通过**循环双向链表连接**（方便 $O(1)$ 时间切断子树）

* **根链表**：所有树的根节点也通过**循环双向链表连接**。维护一个 `min` 指针直接指向最小根节点（实现 $O(1)$ 的 `FIND-MIN`）

* **势能函数**：用于摊还分析，$\Phi(H) = t(H) + 2m(H)$。其中 $t(H)$ 是树的棵数，$m(H)$ 是被标记（marked）的节点数

**斐波那契堆：势能函数**

* $Degree[x]$ = 节点 $x$ 的度数
* $D(n)$ = 包含 $n$ 个节点的斐波那契堆中任意节点的最大度数
* $Mark[x]$ = 节点 $x$ 的标记（黑色或灰色）
* $t(H)$ = 树的数量
* $m(H)$ = 被标记节点的数量
* $\Phi(H) = t(H) + 2m(H)$ = 势能函数

## 2. 斐波那契堆的插入

* **插入操作 (Insert)：**
    1. 创建一个只包含单节点的新树
    2. 将其添加到 `min` 指针的左侧
    3. 更新 `min` 指针

* **运行时间：** 摊还 $O(1)$

## 3. 斐波那契堆的合并

* **合并操作 (Union)：**
    1. 将两个斐波那契堆的根链表拼接起来
    2. 根链表是循环双向链表
* 拼接两个根链表，并更新 `min` 指针
* **运行时间：** 摊还 $O(1)$

## 4. 提取最小元素

由于之前采取 “懒惰” 策略，删除最小值时需要集中整理：

* **操作步骤**：
    1. **摘除最小根**：找到 `min` 指针指向的节点，将其所有孩子拆下并加入根链表，然后删除该节点
    2. **整合（Consolidate）**：这是最耗时的部分。使用一个辅助数组 `A`（按度数索引）。遍历根链表，如果发现两棵树度数相同，就合并它们（键值大的挂到小的下面）。不断重复，直到根链表中所有树的度数**互不相同**
* **时间复杂度**：实际代价为 $O(D(n) + t(H))$，摊还代价为 **$O(D(n))$**，即 $O(\log N)$

## 5. 降低键值（Decrease Key）与级联剪枝

这是斐波那契堆最精妙的地方，分为三种情况：

* **Case 0（不违反堆性质）**：降键后，依然大于等于父节点。直接修改，更新 `min` 即可
* **Case 1（违反堆性质，且父节点未标记）**：
    1. 将节点 $x$ 从父节点切断，加入根链表，更新 `min`
    2. **标记父节点**（Mark）
* **Case 2（违反堆性质，且父节点已被标记）**：触发**级联剪枝（Cascading Cut）**：
    1. 切断 $x$ 加入根链表
    2. 切断父节点加入根链表，清除其标记
    3. 向上递归检查祖父节点，如果祖父也被标记了，继续切断向上递归，直到遇到未标记的节点或根节点
* **时间复杂度**：通过势能分析，其摊还时间复杂度为 **$O(1)$**

## 6. 删除节点（Delete）

* **操作步骤**：
    1. 将目标节点的键值减小至 $-\infty$（触发冒泡到根）
    2. 执行 `EXTRACT-MIN`
* **时间复杂度**：摊还 **$O(\log N)$**

## 7. 最大度数界限证明

* **核心引理**：含 $N$ 个节点的斐波那契堆，任意节点的最大度数 $D(N) \le \log_\phi N$（$\phi = \frac{1+\sqrt{5}}{2}$ 为黄金分割比，约 1.618）
* **证明思路**：
    1. 设度数为 $k$ 的节点最小可能子树大小为 $s_k$
    2. 因为“级联剪枝”规则，一个节点最多失去一个孩子。因此，一个度数为 $k$ 的节点，其第 $i$ 个孩子的度数至少是 $i-2$
    3. 推导得出 $size(x) \ge 2 + \sum_{i=2}^k s_{i-2}$，根据归纳法，下界符合斐波那契数列 $F_{k+2}$，从而证明 $size(x) \ge \phi^k$

# 三、Disjoint Sets 不相交集（并查集）

## 1. 概述与操作

* **目的**：维护一组互不相交的动态集合，常用于无向图的连通分量、聚类等
* **基本操作**：
    1. `MAKE-SET(x)`：创建一个只包含 $x$ 的新集合
    2. `UNION(x, y)`：合并包含 $x$ 和 $y$ 的两个集合
    3. `FIND-SET(x)`：返回包含 $x$ 的集合的**代表元**
* **复杂度参数**：$n$ 为 `MAKE-SET` 次数，$m$ 为总操作次数（$m \ge n$）

## 2. 链表实现（Linked-List）

* **基础实现**：每个集合是一个链表，代表元是头节点。最坏情况下连续合并会导致 $\Theta(n^2)$ 的总时间
* **加权合并启发式（Weighted-Union Heuristic）**：每个链表记录长度，**总是把较短的表拼接到较长的表后面**
* **复杂度**：每个对象的指针最多更新 $\lceil \log n \rceil$ 次。总时间复杂度优化至 **$O(m + n \log n)$**

## 3. 有根树实现（Disjoint-Set Forests）

* **结构**：每个集合是一棵有根树，根节点即为代表元
    * `MAKESET` 建单节点树
    * `FIND-SET` 沿父指针爬到根
    * `UNION` 让一棵树的根指向另一棵树的根

## 4. 两种核心优化启发式

* **按秩合并（Union by Rank）**：每个节点维护一个 `rank`（树高的上界）。合并时，将秩小的根指向秩大的根；若秩相等，任选一个作为根，并让其秩加 1
* **路径压缩（Path Compression）**：在 `FIND-SET` 过程中，让查找路径上的**每个节点都直接指向根节点**。这不会改变节点的秩

## 5. 最终复杂度

* **定理**：使用“按秩合并”和“路径压缩”的不相交集森林，其摊还时间复杂度为 **$O(\alpha(n))$**
* $\alpha(n)$ 是**反阿克曼函数**，其增长极其缓慢。在实际可能遇到的任何应用中，$\alpha(n) \le 4$。因此，可以认为每次操作的摊还时间几乎是 **$O(1)$** 常数级别
